# Rpc.Executor 架构说明

## 两个执行器

| 执行器 | 入口 | 用途 |
|---|---|---|
| `Rpc.Executor.RpcExecutor` | `ExecuteAsync(RpcRequest)` | 字符串协议：服务名/方法名/参数数组，配合 `IMethodResolver`/`IInvoker` |
| `VoyageForge.Rpc.Runtime.Handlers.RpcExecutor` | `Send` / `SendAsync` | 强类型：请求类型 → `IRequestHandler` / `IAsyncRequestHandler` |

## 字符串协议链路

```
RpcRequest
  → ct 检查
  → ServiceRegistry.TryGet(ServiceName)
  → IMethodResolver.TryResolve(ServiceName, MethodName, args)
  → IArgumentConverter.TryConvert（逐项绑定，注入 CancellationToken）
  → IInvoker.InvokeAsync(Slot, instance, boundArgs)
  → RpcResponse.Ok / RpcResponse.Fail
```

错误码：`SERVICE_NOT_FOUND`、`METHOD_NOT_FOUND`、`METHOD_AMBIGUOUS`、`ARGUMENT_BIND_ERROR`、`CANCELLED`；业务异常用异常类型全名。

## 幂等缓存

`IdempotencyCache` 默认开启：

- TTL 5 分钟、容量 1024（可配置）；
- 只缓存成功响应；
- `RequestId == 0` 不参与；
- 命中直接返回，不执行处理器。

## MessageId 与源生成器

- `[RpcMessage(1001)]` 显式编号；
- 生成器 `RpcMessageTypeIdGenerator` 生成 `RpcMessageIds` + `RpcMessageTypeMap`；
- 运行时兜底 `RpcMessageTypeRegistry`；
- 生成器源码位于 `CodeGen~`，通过 `Build-CodeGen.ps1` 构建并部署到 `Runtime/Analyzers`。

## 强类型处理器

- 一个请求类型只允许一个处理器（同步或异步互斥）；
- `Send` 只走同步，`SendAsync` 只走异步，不匹配直接抛异常；
- 处理器目录由 `RpcHandlerGenerator` 生成，`RpcHandlerCatalogCache` 按程序集缓存。
