# 源代码生成器说明

`Rpc.Executor` 包含三个 Roslyn 生成器，源码在 `CodeGen~/Rpc.Executor.CodeGen`（独立 `netstandard2.0` 项目，不参与 UPM 导入）。产物是普通 C# 源码，运行时不再依赖 Roslyn。

## 1. `RpcGenerator` —— 分发器 + 调用端代理

### 触发条件

- 扫描 `[RpcService]` 标注的非泛型 `interface` / `class`；
- 只收集契约自身声明的 `public instance` 方法（不展开继承接口）；
- 排除 `CancellationToken`（框架注入，不参与 MethodId 与 Payload）。

### 返回值约定（必须）

契约方法返回值**必须**是以下形式，否则生成器报告诊断 `RPC004`：

| 契约返回类型 | 含义 |
|---|---|
| `RpcResponse<T>` | 同步，带数据 |
| `Task<RpcResponse<T>>` | 异步，带数据 |
| `RpcResponse` | 同步，无数据 |
| `Task` / `void` | 异步/同步，无返回值 |

生成器用 `ExtractBusinessType` 从 `RpcResponse<T>` / `Task<RpcResponse<T>>` 提取业务类型 `T`，用于生成代理与 `Pack(response.Data)`。

### 参数规则

| 参数数量 | 调用端 Payload | 服务端 dispatch |
|---|---|---|
| 0 | 空 `byte[]` | 不读 Payload |
| 1 | `Pack(arg0)`（直接序列化参数类型） | `Unpack<参数类型>(payload)` |
| 2+ | `Pack((a, b, ...))`（ValueTuple） | `Unpack<(T0 a, T1 b, ...)>(payload)` |

`ValueTuple` 是 struct（值类型），MemoryPack 原生支持，**无装箱**；不再生成 DTO 类。

### 生成文件

**`RpcGeneratedDispatcher.g.cs`**（命名空间 `VoyageForge.Rpc.Generated`）：

```csharp
public static class RpcMethodIds { public const ulong Method_0 = 0x...UL; }

public sealed class RpcGeneratedDispatcher : IGeneratedRpcDispatcher
{
    // MethodId / Slot / IsAsync / ResultType / ParameterTypes
    private static readonly MethodDescriptor[] s_methods = { ... };

    // 方法名回退：args 为空时按名称直接命中；否则按数量 + 可转换性评分选重载
    public bool TryResolve(string serviceName, string methodName, object[] args, out MethodDescriptor descriptor);

    // Slot switch：反序列化参数 → 调业务 → 补 Success → Pack(response.Data)
    public async Task<byte[]> DispatchAsync(int slot, object instance, byte[] payload, CancellationToken ct);
}
```

**`RpcGeneratedClients.g.cs`**（同名空间）：每个契约一个 `static class {Contract}Client` 扩展方法：

```csharp
public static class IUserServiceClient
{
    public static Task<RpcResponse<string>> GetName(this ServicesMap api, int userId);
    public static Task<RpcResponse<UserInfo>> UpdateUser(this ServicesMap api, string id, int level);
}
```

内部直接 `Pack(arg0)` / `Pack((a, b))` 后调 `api.CallAsync<T>(service, method, payload)`——**不经过 `object[]`，无装箱**。

### 诊断

| 诊断 | 含义 |
|---|---|
| `RPC001` | 方法规范 key 重复或 FNV-1a 64 位碰撞 |
| `RPC002` | 不支持的签名（static/泛型/ref/out/in/指针/`ValueTask`/`async void`） |
| `RPC003` | 无效服务声明（非 class/interface、开放泛型、服务名为空） |
| `RPC004` | 返回值未用 `RpcResponse` 包裹 |

### 使用

```csharp
IGeneratedRpcDispatcher dispatcher = new RpcGeneratedDispatcher();
RpcExecutor executor = new RpcExecutor(
    registry,
    new GeneratedMethodResolver(dispatcher),
    new GeneratedRpcInvoker(dispatcher));

ServicesMap api = new ServicesMap(executor);
RpcResponse<int> add = await api.Add(3, 4);   // 生成代理
```

## 2. `RpcHandlerGenerator` —— 强类型处理器目录

- 扫描继承 `RequestHandlerBase` / `AsyncRequestHandlerBase` 的类，或直接实现 `IRequestHandler<TRequest,TResponse>` / `IAsyncRequestHandler<TRequest,TResponse>` 的类；
- 产物 `RpcHandlerCatalog.g.cs`：`[assembly: RpcHandlerCatalogAttribute]` + 请求类型 → 处理器单例；
- 诊断 `RPCHANDLER001`：同一请求类型注册多个处理器。

```csharp
EchoResponse response = executor.Send<EchoRequest, EchoResponse>(new EchoRequest { Text = "hi" });
```

## 3. `RpcMessageTypeIdGenerator` —— 消息 MessageId

- 扫描 `[RpcMessage(ushort)]`；显式编号优先，未标注从 `1000` 自动编号（按类型全名排序，保证稳定）；
- 产物 `RpcMessageIds.g.cs`：`RpcMessageIds` + `RpcMessageTypeMap.TryGetMessageId/TryGetType`；
- 运行时兜底：`RpcMessageTypeRegistry`。

## 构建与部署

```powershell
.\Build-CodeGen.ps1
```

1. `dotnet build` 生成 `Rpc.Executor.CodeGen.dll`（netstandard2.0，Roslyn 4.1，`LangVersion 9.0`）；
2. 复制到 `Runtime/Analyzers/Rpc.Executor.CodeGen.dll`；
3. 生成 `.meta`，Asset Label 必须是 `RoslynAnalyzer`。

> Unity 的源生成器是编译进程内加载的 analyzer：**修改生成器源码后必须重启 Unity** 才会重新加载；普通重编不会刷新。

## 常见问题

- **生成代码没出现**：确认 DLL 的 Asset Label 为 `RoslynAnalyzer`、没有编译错误、Unity 已重启；
- **`CS0579 Duplicate RpcHandlerCatalogAttribute`**：不要手写 `[assembly: RpcHandlerCatalog]`；
- **代理返回 `RpcResponse<RpcResponse<T>>`**：说明 Unity 还在用旧版生成器，重启 Unity；
- **`RpcResponse<T> is not registered`**：生成器产物还在 `Pack(response)`（旧版），应为 `Pack(response.Data)`，重启 Unity 后重编。
