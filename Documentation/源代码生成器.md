# 源代码生成器说明

`Rpc.Executor` 包含三个 Roslyn 生成器，都在 `CodeGen~/Rpc.Executor.CodeGen`（独立 `netstandard2.0` 项目，不参与 UPM 导入）。生成的产物都是**普通 C# 源码**，编译后运行时不再依赖 Roslyn。

## 1. `RpcGenerator` —— 字符串协议分发器

### 触发条件

- 扫描 `[RpcService]` 标注的**非泛型** `interface` / `class`；
- 只收集契约自身声明的 `public instance` 方法（不展开继承接口）；
- 排除 `CancellationToken`（框架注入，不参与 MethodId 和请求参数）。

### 生成文件

`RpcGeneratedDispatcher.g.cs`（命名空间 `VoyageForge.Rpc.Generated`）：

```csharp
public static class RpcMethodIds
{
    // FNV-1a 64 位稳定 MethodId，Slot 为生成顺序
    public const ulong Method_0 = 0x...UL;
    public const ulong Method_1 = 0x...UL;
}

public sealed class RpcGeneratedDispatcher : IGeneratedRpcDispatcher
{
    // 每个方法一条描述符：ServiceName / MethodName / MethodId / Slot
    // / IsAsync / ResultType / ParameterTypes（含 CancellationToken）
    private static readonly MethodDescriptor[] s_methods = { ... };

    // 按服务名、方法名、参数数量、参数可转换性评分选择唯一重载
    public bool TryResolve(string serviceName, string methodName, object[] args, out MethodDescriptor descriptor);

    // 按 Slot 生成强类型 switch：直接 ((IContract)instance).Method(...)
    public Task<object> DispatchAsync(int slot, object instance, object[] args, CancellationToken ct);
}
```

### 生成内容要点

- **`RpcMethodIds` 常量**：每个公开方法一个 `Method_<Slot>` 常量；
- **描述符数组**：`MethodId`、`Slot`、`IsAsync`、`ResultType`、`ParameterTypes`（含 `CancellationToken`）；
- **重载解析**：参数数量匹配 + 类型可转换性评分；并列最优抛 `RpcMethodAmbiguousException`；
- **Slot switch**：`case <Slot>:` 直接调用业务方法，同步/`Task`/`Task<T>`/`void` 分别处理，不走反射。

### 使用

```csharp
IGeneratedRpcDispatcher dispatcher = new RpcGeneratedDispatcher();
RpcExecutor executor = new RpcExecutor(
    registry,
    new GeneratedMethodResolver(dispatcher),
    new GeneratedRpcInvoker(dispatcher));
```

### 诊断

| 诊断 | 含义 |
|---|---|
| `RPC001` | 方法规范 key 重复或 FNV-1a 64 位碰撞 |
| `RPC002` | 不支持的签名（static/泛型/ref/out/in/指针/`ValueTask`/`async void`） |
| `RPC003` | 无效服务声明（非 class/interface、开放泛型、服务名为空） |

## 2. `RpcHandlerGenerator` —— 强类型处理器目录

### 触发条件

- 扫描继承 `RequestHandlerBase` / `AsyncRequestHandlerBase` 的类；
- 也扫描直接实现 `IRequestHandler<TRequest,TResponse>` / `IAsyncRequestHandler<TRequest,TResponse>` 的类（一个类可多个）。

### 生成文件

`VoyageForge.Rpc.Generated.RpcHandlerCatalog.g.cs`：

```csharp
[assembly: RpcHandlerCatalogAttribute(typeof(RpcHandlerCatalog))]

internal sealed class RpcHandlerCatalog : IRpcHandlerCatalog
{
    // 每个请求类型一个处理器单例
    private static readonly object Handler0 = new YourHandler();

    public bool TryGet(Type requestType, out object handler, out bool isAsync) { ... }
}
```

### 使用

运行时 `RpcHandlerCatalogCache` 遍历程序集找到该目录并缓存，强类型 `RpcExecutor.Send` / `SendAsync` 按请求类型查表。

### 诊断

| 诊断 | 含义 |
|---|---|
| `RPCHANDLER001` | 同一请求类型注册了多个处理器 |

## 3. `RpcMessageTypeIdGenerator` —— 消息 MessageId

### 触发条件

- 扫描带 `[RpcMessage(ushort)]` 的类型；
- 显式编号优先；未标注类型从 `1000` 自动编号（按类型全名排序，保证稳定）。

### 生成文件

`RpcMessageIds.g.cs`：

```csharp
public static class RpcMessageIds
{
    public static readonly MessageId YourMessage = new MessageId(1001);
}

public static class RpcMessageTypeMap
{
    public static bool TryGetMessageId(Type type, out MessageId messageId);
    public static bool TryGetType(MessageId messageId, out Type type);
}
```

### 使用

传输层/业务层可用生成映射把 TypeId 与具体消息类型对应；未生成时可用运行时兜底 `RpcMessageTypeRegistry`。

## 构建与部署

```powershell
.\Build-CodeGen.ps1
```

脚本会：

1. `dotnet build` 生成 `Rpc.Executor.CodeGen.dll`（`netstandard2.0`，Roslyn 4.1，`LangVersion 9.0`）；
2. 复制到 `Runtime/Analyzers/Rpc.Executor.CodeGen.dll`；
3. 生成 `.meta`，并提示在 Unity Inspector 确认 Asset Label 为 `RoslynAnalyzer`。

> 只改 Runtime 代码不需要重新构建生成器；只有修改 `CodeGen~` 源码或升级 Roslyn 版本时才需要。

## 常见问题

- **Unity 控制台没有生成代码**：确认 DLL 的 Asset Label 为 `RoslynAnalyzer`，且没有编译错误；
- **`CS0579 Duplicate RpcHandlerCatalogAttribute`**：不要手动写 `[assembly: RpcHandlerCatalog]`，交给生成器；
- **生成器 DLL 加载失败**：检查 Unity 的 Roslyn 版本与 csproj 的 `Microsoft.CodeAnalysis.CSharp` 是否匹配（当前 4.1.0）；
- **示例测试找不到处理器**：测试程序集的 handler 应由生成器生成目录，不需要手动 catalog。
